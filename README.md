# Система классификации токсичных комментариев

## 1. Постановка задачи
**Цель**: Разработка NLP-системы для выявления и категоризации токсичных комментариев в пользовательском контенте в реальном времени.

**Формат вывода**: Для заданного текста система выдает непрерывные вероятностные оценки (scores) по 6 независимым измерениям токсичности: `toxic`, `severe_toxic`, `obscene`, `threat`, `insult` и `identity_hate`.

**Бизнес-ценность**: Автоматизация модерации контента, позволяющая платформам эффективно помечать и фильтровать вредоносные материалы без полностью ручного вмешательства.

## 2. Архитектура
Система использует клиент-серверную архитектуру. Фронтенд-компоненты отправляют сырой текст в API-шлюз (FastAPI). Бэкенд выступает в роли слоя инференса (serving layer), где предобученные ML-модели (например, TF-IDF + LogReg / DistilBERT-LoRA) обрабатывают запрос и предсказывают распределение классов перед отправкой JSON-ответа.

```mermaid
flowchart LR
    Client([Client App / Web UI]) -->|HTTP POST| API(FastAPI Backend)
    API -->|Pre-process| Engine(Inference Engine)
    Engine --> Model[(Trained Model Weights)]
    Model -.-> Engine
    Engine --> API
    API -->|JSON Response| Client
```

## 3. Компоненты системы и ML-пайплайн

### 3.1. Данные и пайплайн предобработки (`src/`)
*   **Источник данных**: Датасет Jigsaw Toxic Comment Classification Challenge (~160 тыс. размеченных комментариев).
*   **Сложности**: Сильный дисбаланс классов (~90% комментариев нетоксичны, встречаются редкие классы вроде `threat`).
*   **Предобработка**: Удаление стоп-слов, приведение к нижнему регистру, очистка синтаксиса (`src/preprocess_data.py`).
*   **Оптимизация**: Жесткая классификация по порогу 0.5 дает низкий F1-macro из-за дисбаланса. Кастомный оптимизатор порогов (`find_optimal_threshold.py`) максимизирует F1-score для каждого класса индивидуально.

### 3.2. Алгоритмы машинного обучения
Оценивались несколько базовых и SOTA-моделей с учетом соотношения производительности и вычислительных затрат:
1.  **Базлайн (TF-IDF + Логистическая регрессия)**: Чрезвычайно быстрый инференс. Устанавливает верхнюю планку для линейного маппинга (AUC: 0.972). Показывает, что токсичность сильно коррелирует со строгим лексиконом («слова-триггеры»).
2.  **Эмбеддинги (FastText + LogReg)**: Подход на основе семантического сходства без моделирования последовательности.
3.  **Глубокое обучение (BiLSTM)**: Рекуррентная агрегация контекста устраняет проблему «размытия слов-триггеров», свойственную average pooling (AUC: 0.98).
4.  **Трансформеры (DistilBERT + LoRA)**: Эффективное дообучение (fine-tuning) DistilBERT. State-Of-The-Art обобщающая способность для классификации (AUC: ~0.98).
5.  **RAG + DistilBERT + LoRA**: Retrieval-Augmented вариант, где к комментарию добавляется краткий контекст из топ-K наиболее похожих сообщений (TF-IDF + NearestNeighbors). Модель обучается на паре «комментарий + контекст», что особенно полезно для редких классов.

### 3.3. RAG-версия модели (`lora-rag.ipynb`)
*   **Retrieval слой**: TF-IDF + NearestNeighbors по тренировочным комментариям.
*   **Контекст**: топ-K ближайших комментариев конкатенируются в один текстовый блок (усеченный до `RAG_MAX_CHARS`).
*   **Вход модели**: пара «comment_text + context_text» с токенизацией пар и ограничением `MAX_LENGTH`.

### 3.4. API для инференса (`app/`)
*   **Фреймворк**: FastAPI, выбран за асинхронную производительность и автоматическую генерацию Swagger (`/docs`).
*   **Возможности**: Содержит эндпоинт (`/api/classify`) для обработки и сериализации текста. Реализован рендеринг Jinja2 для веб-интерфейса.

## 4. Спецификация API
### `POST /api/classify`
*   **Описание**: Принимает сырой текст и возвращает оценки уверенности классификатора по категориям.
*   **Тело запроса**: 
    ```json
    { "text": "Sample user comment text" }
    ```
*   **Ответ (200 OK)**:
    ```json
    {
      "toxic": 0.85,
      "severe_toxic": 0.05,
      "obscene": 0.60,
      "threat": 0.01,
      "insult": 0.75,
      "identity_hate": 0.02
    }
    ```

## 5. Архитектура развертывания
Система спроектирована для легкой воспроизводимости и развертывания в любых средах.
*   **Контейнеризация**: `Dockerfile` упаковывает окружение из `requirements.txt`, Python-сервер и артефакты обученных моделей (`.pkl`/`.safetensors`).
*   **Оркестрация**: `compose.yaml` (Docker Compose) упрощает запуск и конфигурацию портов (`8000:8000`).
```bash
docker-compose up --build
```
## 6. Компромиссы и системный анализ
*   **Задержка (Latency) против Точности (Accuracy)**: Модели на основе TF-IDF обрабатывают запросы за доли миллисекунды, что идеально для модерации с высокой пропускной способностью (High-RPS). DistilBERT дает лучший контекстуальный анализ, но требует GPU-ускорителей для соблюдения жестких SLA при высоких нагрузках.
*   **Потребление памяти против Дообучения**: Стандартный тюнинг трансформера требует больших объемов VRAM. Интеграция **PEFT (LoRA)** позволила обучать только конкретные блоки внимания (`q_lin`, `v_lin`), заморозив базовую модель и сгенерировав компактные веса адаптеров (`toxic_lora/`).
*   **Интерпретируемость**: Сложные нейросети работают как черные ящики. В пайплайн интегрирован `SHAP` (`src/shap_show.py`) для анализа и визуализации локальной важности отдельных слов/токенов.

## 7. Сводка метрик

| Архитектура / Модель  | ROC-AUC | F1 (macro) | F1 (micro) | Precision | Recall |
|-----------------------|---------|------------|------------|-----------|--------|
| **DistilBERT + LoRA** | **~0.98** | 0.46 | 0.76 | 0.62 | 0.43 |
| RAG + DistilBERT + LoRA | 0.974 | 0.40 | 0.68 | 0.41 | 0.65 |
| BiLSTM + FastText     | **0.98** | 0.61 | 0.75 | 0.42 | 0.63 |
| TF-IDF + LogReg       | 0.972 | 0.59 | 0.71 | 0.39 | 0.61 |
| BERT (Features) + LR  | 0.977 | 0.60 | 0.71 | 0.40 | 0.63 |

**Примечание**: в случай RAG была проведена TF-IDF-векторизация, что ограничело потенциал модели.
